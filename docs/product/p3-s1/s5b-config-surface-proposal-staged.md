## 2. 范围分析

- **配置面缺口**：S5 落地了机制层（谁生成 LlmProposal 的抽象与规则），未落地用户配置面（用户如何添加自己的 key、选择提供方 / 模型）。产品「活起来」的最后一公里：终端用户经页面配置自己的提供方凭据。
- **多提供方配置**：用户可配置多个不同提供商的对应模型——配置模型为多记录（提供方 → 模型 → key），用户经页面选择启用配置。
- **凭据存储**：key 持久化 = 敏感凭据静态存储——要素 4 两层加密 + 密钥分离适用；加密密钥不随数据同处存储（V1：加密密钥经环境变量注入，与密文分离）。
- **范围边界**：本切片为暴露层 + 机制层扩展——策略语义（policy_v2.3.0）/ 状态机（state_machine_v1.5.0）/ 事件契约（C6）不变；提供方构造规则族（S5A-SEMANTIC-FREEZE-01 §1 D-2）不变——新增提供方仍走「提案 → 裁决 → 冻结 → 证据」链。

## 3. 裁决选项（D-1…D-6——选项文本经裁决版本化冻结）

### D-1：配置面形态

- **选项 A（实现方建议）**：页面表单 + 环境变量双形态——用户经页面添加 / 编辑 / 删除提供方配置（provider / model / key）；环境变量形态保留（证据 / 测试环境优先——证据注入缝仍为最高优先级）。运行时配置解析优先级：证据注入缝 > 页面持久化配置 > 环境变量 > 合成默认。（裁决后生效——见 §6）
- **选项 B**：仅环境变量——与产品负责人指令冲突（用户无法在页面添加 key）；实现方不推荐。
- **选项 C**：仅页面（移除环境变量形态）——证据 / 测试环境纪律受损（证据执行器依赖环境变量形态注入）；不推荐。

### D-2：API key 存储机制

- **选项 A（实现方建议）**：加密持久化——key 密文持久化（静态加密——要素 4 两层机制之一）；加密密钥与密文分离（密钥分离——要素 4）：V1 加密密钥经环境变量注入（`EXPERIENCE_CONFIG_ENCRYPTION_KEY`），不随数据同处存储；存储位置 = 中国大陆（cn）/ 阿里云 / 云存储（要素 2——与产品数据同要素）；key 明文仅运行期内存持有，不进日志、不进证据产物、不进 git。（裁决后生效——见 §6）
- **选项 B**：不持久化（页面输入仅会话内存）——重启后需重新输入，体验断裂；仅作备选。
- **选项 C**：环境变量单一路径——现状，无法满足页面化指令。

### D-3：多提供方配置模型

- **选项 A（实现方建议）**：多记录配置——每提供方一条配置（provider 标识 / model 名 / key 密文引用），可多条并存；用户经页面选择启用配置（启用配置 = 运行时使用该配置的 provider 规则与 key）；未启用配置不影响运行时。（裁决后生效——见 §6）
- **选项 B**：单提供方单配置——与「配置多个不同提供商的对应模型」指令冲突。
- **选项 C**：提供方自动池 / 智能路由——V1 不推荐（路由语义本身须另行版本化决策，超出本切片）。

### D-4：暴露面（HTTP 路由）

- **选项 A（实现方建议）**：新增配置管理路由（HTTP 面扩展——经本切片裁决纳入；配置读写 API + 页面渲染）。访问控制按产品使用形态定义：个人使用形态（本机访问——V1 默认）；多用户形态须另行版本化决策。（裁决后生效——见 §6）
- **选项 B**：仅进程内配置（无页面）——与产品负责人指令冲突。
- **选项 C**：页面直连持久化（无 API 中间层）——不推荐（读写纪律与审计面缺失）。

### D-5：隐私再确认界面化

- **选项 A（实现方建议）**：页面内启用确认流——启用提供方配置前，页面内确认该提供方 DPA / 数据处理条款与已签署六要素一致性；确认记录持久化（通用模板——提供方名称于确认时填写，不写死任何提供方——S5A-SEMANTIC-FREEZE-01 v1.1.0 D-5）；确认人 = 产品负责人 + 安全负责人（用户本人，PD-15 双重身份）；确认前该配置不得启用。（裁决后生效——见 §6）
- **选项 B**：线下签署后启用——确认记录不持久化于产品，审计链弱；不推荐。

### D-6：实施路径

- **选项 A（实现方建议）**：一次性实施——配置模型 + 加密存储 + 配置管理路由 + 页面 UI + 启用确认流 → 动态证据 S5B-F1-0001（配置 CRUD / 加密存储 / 运行时加载 / 启用确认 / 访问控制）+ 基线回归（G3-GOLDEN-0001 再生 + S2B-0001 重跑）→ S5B G5 评测链（16 项框架范围定义提案另行 staged）。（裁决后生效——见 §6）
- **选项 B**：分批（先存储 → 再页面）——不推荐（单切片可闭合；分批产生中间未完成态）。
- **选项 C**：仅冻结不实施——保留为备选。

## 4. 选项 A 实施影响（D-1…D-6 全项 A）

- 配置存储：加密持久化（密文存储——静态加密；加密密钥经 `EXPERIENCE_CONFIG_ENCRYPTION_KEY` 环境变量注入，与密文分离）；存储位置要素 2（cn / 阿里云 / 云存储）。
- 配置管理路由：新增 HTTP 面（配置 CRUD API——读操作不返回 key 明文）；访问控制按个人使用形态定义（V1 本机访问——多用户形态另行版本化决策）。
- 页面 UI：提供方配置管理（添加 / 编辑 / 删除 / 启用选择 + 启用前隐私确认流）。
- 运行时配置加载扩展：页面持久化配置优先于环境变量（优先级：证据注入缝 > 页面持久化配置 > 环境变量 > 合成默认）；ProviderLlmGateway 经持久化配置构造（provider 规则仍以 S5A-SEMANTIC-FREEZE-01 登记集为界——未登记提供方拒绝启用）。
- 无策略 / 状态机 / 事件契约变更（policy_v2.3.0 / state_machine_v1.5.0 / C6 不变）。
- 动态证据计划：S5B-F1-0001（配置 CRUD × 正常 / 负向 / 边界 / 故障恢复四维度 + 加密存储静态核验（密文非明文落盘）+ 运行时加载（页面配置优先于环境变量）+ 启用确认流（未确认配置不得启用）+ 访问控制 + key 不泄漏（日志 / 响应 / 证据产物无明文））+ 基线回归。
- 与 S5 衔接：S5A-F1-0001（LLM 模式结构证据）执行前置不变——API key 由用户在页面添加后，证据执行经页面配置形态注入（或环境变量形态——两种形态均支持，证据执行器经环境变量形态保持既有纪律）。

## 5. 明确非结论

- 本提案不构成任何 Gate 状态变化；不设置任何产品 Gate 为 PASS（E5 §2）。
