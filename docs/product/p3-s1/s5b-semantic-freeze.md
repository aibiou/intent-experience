## 1. 语义定义（D-1…D-6 裁决原文——版本化冻结）

### D-1：配置面形态

- **页面表单 + 环境变量双形态**：用户经页面（`/config`）添加 / 编辑 / 删除提供方配置（provider / model / endpoint / key——v1.1.0：任何 chat-completions 兼容提供方均可自定义，填写提供方名称、端点（chat/completions URL）、模型名与 API key，无需登记）；环境变量形态保留（证据 / 测试环境优先——证据注入缝仍为最高优先级）。
- **运行时配置解析优先级**：证据注入缝（`EXPERIENCE_LLM_GATEWAY_SEAM=1`）> 页面持久化配置（已启用配置）> 环境变量 LLM 模式（`EXPERIENCE_LLM_MODE=provider`）> 合成默认。
- **即时生效**：页面持久化配置经 `PersistedConfigLlmGateway` 委托网关每次调用解析——启用 / 禁用 / 删除经配置面即时生效（单进程内存缓存，无需重启）。
- **SEAM-INERT 不变式**：无任何配置时委托网关委托 `SyntheticLlmGateway`——与 S1–S4 默认形态行为完全一致（零行为变化）。

### D-2：API key 存储机制

- **静态加密**：key 仅以 AES-256-GCM 密文持久化（密文形态 `base64(iv).base64(ciphertext).base64(tag)`）。
- **密钥分离**：加密密钥经环境变量 `EXPERIENCE_CONFIG_ENCRYPTION_KEY` 注入（32 字节 hex），不随密文同处存储；缺失或非法时拒绝持久化（`CONFIG_ENCRYPTION_KEY_MISSING` / `CONFIG_ENCRYPTION_KEY_INVALID`——不静默降级）。
- **存储位置**（要素 2）：生产形态 = 中国大陆（cn）/ 阿里云 / 云存储；本机开发形态为本地 `data/` 目录（`.gitignore` 排除，绝不提交）。
- **明文纪律**：key 明文仅运行期内存持有，不进日志、不进证据产物、不进 git。
- **读操作纪律**：list / 查询永不返回 key 明文或密文——仅 `hasKey` 标记存在。

### D-3：多记录配置模型

- 每提供方一条配置（provider 标识 / model 名 / key 密文引用），可多条并存（用户可配置多个不同提供商的对应模型）。
- 同时至多一条启用（单激活）——启用新配置自动关闭既有启用配置。
- 启用配置 = 运行时使用该配置的已解析端点（记录端点优先、预设缺省回退——v1.1.0：`PROVIDER_PROFILES` 仅作预设）与 key 构造 `ProviderLlmGateway`（chat-completions 兼容协议形态：`/chat/completions` + Bearer 鉴权；v1.3.0 端点容错——端点缺 `/chat/completions` 后缀时自动补全，用户可填写提供方文档中的 API Base URL）。
- 未启用配置不影响运行时。

### D-4：暴露面（HTTP 路由）

- 配置管理路由：`/api/config`（列表 / 新增）、`/api/config/[id]`（查询 / 更新 / 删除）、`/api/config/[id]/confirm`（隐私再确认签署）、`/api/config/[id]/enable`、`/api/config/[id]/disable`、`/api/config/profiles`（提供方预设族——缺省端点 / 模型自动填充，非准入清单——v1.1.0）、`/api/config/models`（模型列表识别——用户触发，双形态：显式 `{endpoint, api_key}`（保存前——仅发送用户填写的端点与 key）/ 已存 `{config_id}`（保存后——服务端解密该配置已存 key 调用，key 任何形态不返回客户端——与 D-2 读操作纪律一致；v1.3.0）；响应仅含模型 id 列表——key 任何形态不返回、不记录；错误信息仅含状态码——v1.2.0）、`/api/config/status`（运行模式状态——合成演示 / 已启用提供方，不含 key 任何形态）。
- 访问控制：个人使用形态（本机访问——V1 默认）；多用户形态须另行版本化决策。

### D-5：隐私再确认界面化

- **通用模板**：`PRIVACY-RECONFIRM-GENERIC/V1`——提供方名称于签署时填写，产品代码不写死任何提供方。
- **确认人** = 产品负责人 + 安全负责人（用户本人，PD-15 双重身份）。
- **确认记录持久化**；未确认提供方的配置不得启用（`PROVIDER_NOT_CONFIRMED`——启用前置条件）。
- 首个验证提供方（dashscope）的确认为本机制首个实例——于启用前经同一通用模板签署。

### D-6：实施路径

- 一次性实施：配置模型 + 加密存储 + 路由 + 页面 + 确认流 → 动态证据 S5B-F1-0001（配置 CRUD / 加密存储 / 运行时优先级 / 启用确认 / key 不泄漏 / 提供方准入 × 正常 / 负向 / 边界 / 故障恢复四维度）+ 基线回归（G3-GOLDEN-0001 再生 + S2B-0001 重跑）→ S5B G5 评测链（16 项框架范围定义提案另行 staged）。
