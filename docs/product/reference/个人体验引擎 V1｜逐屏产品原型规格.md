# 个人体验引擎 V1

## 逐屏产品原型规格

---

# 一、先确定一条产品铁律

整个产品的所有页面，都遵循：

> **人决定方向，AI降低成本。**

因此每一屏都必须回答五个问题：

1. 用户现在处于什么状态？
2. 用户此刻需要什么？
3. AI能替用户承担什么？
4. AI不能替用户决定什么？
5. 用户如何随时退出？

如果一个页面无法回答这五个问题，就不应该进入 V1。

---

# Screen 01｜首页

## 用户状态

用户刚打开产品。

他可能：

- 很明确地想做某件事
- 有一点无聊
- 想放松
- 想找点新鲜东西
- 想学习但不知道学什么
- 心里有事情但还没有组织成语言
- 单纯不知道为什么打开

所以：

> **不能假设用户有明确需求。**

---

## 页面目标

不是让用户“开始使用 AI”。

而是让用户非常低成本地回答：

> **“我现在大概想要什么？”**

---

## 页面

```text
┌──────────────────────────────┐
│                              │
│                              │
│       现在想要什么？          │
│                              │
│                              │
│   ┌──────────────────────┐   │
│   │       放松一下       │   │
│   └──────────────────────┘   │
│                              │
│   ┌──────────────────────┐   │
│   │      发现点东西      │   │
│   └──────────────────────┘   │
│                              │
│   ┌──────────────────────┐   │
│   │      深入一个问题    │   │
│   └──────────────────────┘   │
│                              │
│   ┌──────────────────────┐   │
│   │       做点什么       │   │
│   └──────────────────────┘   │
│                              │
│           随便看看           │
│                              │
│  ──────────────────────────  │
│  直接告诉我……           🎙   │
│                              │
│          最近的探索           │
│       昨天的那个问题 →       │
│                              │
└──────────────────────────────┘
```

---

## 为什么只有这些？

因为这是**状态入口**。

不是兴趣分类。

用户不用思考：

> “我到底属于哪类用户？”

只需要：

> “我现在比较像哪一种？”

---

## “直接告诉我”

这是最重要的自由入口。

用户可以说：

> “今天特别累。”

> “我想找点刺激的。”

> “我想知道一个奇怪的东西。”

> “我不知道。”

> “我想做一个游戏。”

系统理解自然语言。

---

## 如果用户什么都不想选

页面允许：

> **“不知道”**

甚至可以把它作为语音/文字入口的一种自然表达。

AI：

> “没关系。我随便给你一个，如果不喜欢就换。”

这句话非常重要。

**降低选择压力。**

---

## AI禁止行为

首页不能：

- 自动播放
- 自动弹窗
- 用倒计时制造紧迫感
- 显示热门排行榜
- 强迫登录才能探索
- 一打开就问一堆问题
- 立刻展示十几个推荐

---

# Screen 02｜意图确认

用户点击：

> 发现点东西

## 不应该发生

不要出现：

> “请选择你的兴趣。”

不要出现：

> “请选择主题。”

不要出现：

> “你想了解科学、历史、艺术还是科技？”

这是把AI理解用户的工作重新甩给用户。

---

## 页面

```text
┌──────────────────────────────┐
│                              │
│                              │
│       好，我来找一个。        │
│                              │
│      不需要你提前想主题。     │
│                              │
│                              │
│             ···              │
│                              │
└──────────────────────────────┘
```

持续时间：

**约 0.5–1.5 秒。**

然后直接进入体验。

---

## 为什么这么短？

因为：

> 用户已经表达了足够的意图。

继续询问就是摩擦。

---

# Screen 03｜第一体验入口

这是整个产品最重要的一屏。

## 原则

第一体验不能让用户觉得：

> “AI又给我生成了一篇东西。”

而应该让用户觉得：

> **“诶？这个我想知道。”**

---

## 示例

```text
┌──────────────────────────────┐
│                              │
│          一个问题            │
│                              │
│     如果太阳突然变成         │
│        一个黑洞，             │
│                              │
│       地球会发生什么？       │
│                              │
│                              │
│    答案可能和你想的不一样。  │
│                              │
│                              │
│          开始探索 →          │
│                              │
│                              │
│             换一个            │
└──────────────────────────────┘
```

---

## 这里有两个按钮

### 主操作

> 开始探索

### 次操作

> 换一个

没有：

- 分享
- 收藏
- 点赞
- 评论
- 关注

因为用户现在还没有理由做这些事情。

---

# Screen 04｜第一段体验

用户点击开始。

## 第一原则

**不要一次把答案讲完。**

但也不能故意藏信息骗用户继续。

两者区别很重要。

---

## 示例

```text
如果太阳突然变成
一个质量完全相同的黑洞，

地球不会立刻被吸进去。

因为从引力的角度看，

“太阳变成黑洞”
并不会突然让它变得更重。

真正奇怪的是……

        ↓

如果太阳没有了光，

地球会先经历什么？
```

---

## 这时用户可以：

```text
为什么？
继续
我大概懂了
换一个
```

也可以直接输入：

```text
┌──────────────────────────────┐
│  直接问……                🎙  │
└──────────────────────────────┘
```

---

## 为什么提供“我大概懂了”？

因为：

> 用户不是为了完成产品流程而来的。

如果用户已经理解，他应该能够结束当前层级。

AI不能为了留存强迫：

> “再看一下。”

---

# Screen 05｜用户提问

用户：

> “为什么不会被吸进去？”

## 页面发生变化

从“内容展示”变成：

> **共同思考。**

```text
┌──────────────────────────────┐
│       太阳 → 黑洞             │
│                              │
│       🌑                     │
│          ·                   │
│             🌍               │
│                              │
├──────────────────────────────┤
│                              │
│ 因为黑洞并不会自动产生       │
│ 更强的引力……                 │
│                              │
│ 想象一下：                   │
│ 如果太阳质量完全不变，       │
│ 只是体积缩小……               │
│                              │
├──────────────────────────────┤
│ 继续问……                🎙   │
└──────────────────────────────┘
```

---

## AI此时要判断

```text
用户行为
   ↓
是在追问事实？
还是在表达好奇？
还是想做实验？
还是已经理解？
```

例如：

> “那离近一点呢？”

这不是普通知识问答。

这是：

> **用户正在构建自己的模型。**

系统应该切换体验模式。

---

# Screen 06｜动态体验

AI：

> “我们直接试一下。”

页面进入互动。

```text
┌──────────────────────────────┐
│                              │
│        地球与太阳的距离       │
│                              │
│  ●───────────────●           │

│                              │
│       距离：1 AU             │
│                              │

│                              │
│         拖动试试看            │
│                              │

│ 如果更近，会发生什么？        │
│                              │
│             继续探索 →        │
└──────────────────────────────┘
```

---

## 用户拖动

系统实时变化。

例如：

> 0.8 AU

> 0.5 AU

> 0.2 AU

同时解释：

> “温度开始明显变化。”

用户继续：

> “那如果……”

体验继续。

---

## 关键

这里用户不是：

> 阅读 AI。

而是：

> **操纵一个自己正在理解的世界。**

这是我们真正需要建立的产品体验。

---

# Screen 07｜分支选择

当用户深入以后，系统会判断用户想往哪里走。

但不要突然弹出一个“功能菜单”。

应该自然地问：

> **你现在更想知道哪一个？**

```text
┌──────────────────────────────┐
│                              │
│       这个问题可以往三个      │
│       方向继续。              │
│                              │
│  ┌────────────────────────┐  │
│  │ 为什么会这样？         │  │
│  └────────────────────────┘  │
│                              │
│  ┌────────────────────────┐  │
│  │ 如果真的发生会怎样？   │  │
│  └────────────────────────┘  │
│                              │
│  ┌────────────────────────┐  │
│  │ 我想自己试试看          │  │
│  └────────────────────────┘  │
│                              │
│             随便继续          │
└──────────────────────────────┘
```

---

## “随便继续”

非常重要。

用户不应该被迫做产品经理。

如果他不想选：

> AI自己承担选择成本。

---

# Screen 08｜从探索进入创造

假设用户选择：

> 我想自己试试看。

这里是产品真正的转折点。

不能进入一个传统“AI工具”。

---

## 第一阶段

AI：

> “好，我们一起做。”

然后只问一个最重要的问题。

例如：

> “你最想改变什么？”

用户：

> “我想让这个世界里的时间变慢。”

AI：

> “可以。”

直接改变世界。

---

## 页面

```text

│                              │

│                              │
│ 直接告诉我……            🎙   │
└──────────────────────────────┘
```

# Screen 09｜完成

用户说：

> “这样就可以了。”

系统不能继续制造新的需求。

---

## 页面

```text
┌──────────────────────────────┐
│                              │
│        这次探索完成了。       │
│                              │
│  你从一个问题开始：           │
│                              │
│  如果太阳变成黑洞……          │
│          ↓                   │
│  引力                       │
│          ↓                   │
│  距离                       │
│          ↓                   │
│  自己设计实验                │
│                              │
│                              │
│       [保存这次探索]          │
│                              │
│       [再探索一个]            │
│                              │
│            结束               │
└──────────────────────────────┘
```

---

## “保存”不能默认发生

用户主动选择：

> 保存这次探索。

才进入长期记忆。

否则只保留必要的产品运行数据，不把所有对话都变成“用户记忆”。

---

# Screen 10｜记忆

保存后：

```text
这次探索已经保存。

我记住的是：

你刚刚对“反直觉的科学问题”
产生了兴趣。

我不会把这理解成：
“你以后只喜欢科学。”

如果以后你不想继续这个方向，
随时可以告诉我。
```

---

## 为什么要解释？

因为：

> **记忆是信任问题。**

用户需要知道：

- 记了什么
- 为什么记
- 记忆意味着什么
- 能不能纠正

---

# Screen 11｜第二天

这是产品的真正复访场景。

用户打开。

不是：

> “欢迎回来，有什么可以帮你？”

而是：

```text
┌──────────────────────────────┐
│                              │
│          欢迎回来             │
│                              │
│   昨天我们停在一个问题：      │
│                              │
│   “如果时间真的变慢，        │
│    里面的人自己会感觉到吗？” │
│                              │
│                              │
│       继续昨天 →              │
│                              │
│       今天换点新的            │
│                              │
│       我现在只想放松          │
│                              │
└──────────────────────────────┘
```

---

## 这里有一个非常重要的设计

### “继续昨天”

不是默认选项。

### “今天换点新的”

同样重要。

### “我现在只想放松”

甚至可能更重要。

因为：

> **用户昨天喜欢什么，不等于今天想要什么。**

这是我们“理解人”与“给人贴标签”的根本区别。

---

# 十二、用户拒绝系统时怎么办？

这是 V1 必须重点测试的。

---

## 情况 A：用户说“不感兴趣”

AI：

> “好。”

直接换。

---

## 情况 B：用户说“别总给我这种东西”

AI：

> “明白。以后我会降低这类内容的优先级。”

出现：

> 查看 / 修改这个判断

用户可以进一步说：

> “我不是不喜欢，只是今天不想看。”

系统记录的应该是：

```text
今天不想看
```

而不是：

```text
用户不喜欢
```

这是**时间状态**和**长期偏好**的区别。

---

## 情况 C：用户说“你根本不了解我”

不能辩解。

应该：

> “可能是我判断错了。你愿意的话，可以告诉我你现在更想要什么；也可以什么都不说，我换一种完全不同的。”

这才是人本。

---

# 十三、用户什么都不想说

这是必须支持的。

用户：

> “不知道。”

系统：

> “没关系。”

然后提供一个低压力入口：

> “那我随便给你一个。”

---

# 十四、用户想离开

用户点击退出。

不能：

> “等等！你还可以……”

应该：

```text
现在离开？

这次探索会自动停在这里。

[离开]

[继续]
```

只有一次确认。

---

# 十五、用户长时间没有回应

不能疯狂：

> “还在吗？”

> “要不要继续？”

> “试试看？”

系统应该保持安静。

如果最终退出：

> 正常结束。

---

# 十六、用户连续探索很久

产品应该有“温和提醒”。

例如：

> “已经探索了一段时间了。如果你还想继续，可以继续；如果想停，停在这里也完全可以。”

不要：

> “你已经连续使用 60 分钟！”

不要制造成就感。

---

# 十七、AI错误的时候

假设 AI理解错了。

用户：

> “不是这个意思。”

AI：

> “明白，我刚才把你的意思理解成 A 了。你实际更接近 B。”

然后继续。

---

## 用户不需要承担纠错成本

不能：

> “请从以下选项中重新定义您的需求。”

AI应该自己恢复。

---

# 十八、用户表达模糊

例如：

> “我想做点有意思的。”

系统不要问：

> “请具体描述。”

而应该：

> “可以。我先给你三个完全不同的方向，你不用提前决定。”

然后：

```text
一个可以玩的东西
一个可以探索的问题
一个可以自己创造的东西
```

AI承担不确定性。

---

# 十九、用户表达非常明确

例如：

> “我想做一个小游戏。”

此时不要再走首页。

直接：

> “好。你想先做玩法，还是直接让我给你一个可以玩的雏形？”

甚至：

> “如果你不确定，我先做一个最简单的。”

**明确意图 → 最短路径。**

---

# 二十、语音

语音不是一个“高级功能”。

它解决的是：

> **人不想打字。**

首页：

```text
直接告诉我……
🎙
```

体验中：

```text
继续问……
🎙
```

创作中：

```text
你想改什么？ 🎙
```

语音输入后必须允许用户看到/修改识别结果。

不能因为语音方便，就降低用户控制权。

---

# 二十一、错误状态

## 网络失败

不要：

> Error 500

应该：

> “刚才没接上，我们再试一次。”

---

## AI生成失败

> “这个体验刚才没生成好。”

按钮：

> 再试一次

不要假装已经完成。

---

## 搜索不到可靠答案

AI应该说：

> “这个问题目前没有足够可靠的答案。我可以告诉你目前比较确定的部分，也可以一起看看不同观点。”

**可靠性优先于完整回答。**

---

# 二十二、隐私状态

用户任何时候可以进入：

> 我的 → 控制与隐私

看到：

```text
我记住了什么
----------------
最近的探索
长期偏好
你的作品

AI如何使用这些信息
----------------
当前体验
个性化
推荐

你可以：
----------------
暂停个性化
暂停记忆
修改记忆
删除探索
导出数据
```

---

# 二十三、“暂停记忆”

这是一个非常重要的按钮。

例如用户：

> “今天不想让你记住任何东西。”

点击：

> **暂时不要记住**

页面：

> “好的。从现在开始，新的内容不会进入你的长期记忆。你可以随时恢复。”

这会让用户感觉：

> **记忆是我的，不是产品的。**

---

# 二十四、“为什么给我这个？”

这是一个核心信任功能。

用户点击后：

```text
我给你这个，是因为：

① 你最近主动探索过类似问题
② 你之前倾向于继续深入
③ 这次你选择了“发现点东西”

其中第①点我比较确定，
第②点只是我的推测。
```

这里必须区分：

**事实 / 推断 / 不确定性。**

---

# 二十五、首页的真正智能化

随着系统变好，首页最终不应该永远固定。

可能变成：

```text
现在想要什么？

我猜你今天可能只想轻松一点。

要不要给你一个
3分钟的小探索？

[好]
[我想自己选]
[完全随机]
```

注意：

> **“我猜你”**

而不是：

> “你现在需要……”

AI应该表现出判断，同时承认自己可能错。

---

# 二十六、AI主动性的边界

AI可以：

### 主动推荐

可以。

### 主动提醒昨天的探索

可以。

### 主动发现兴趣变化

可以。

### 主动改变用户状态

不可以。

### 主动制造焦虑来留存

不可以。

### 利用用户脆弱情绪提高使用时间

不可以。

### 在用户明确拒绝后继续推进

不可以。

---

# 二十七、整个产品的“人性化状态机”

我们不能只做用户状态。

还需要：

```text
User State

Curious
Relaxed
Bored
Focused
Tired
Uncertain
Excited
Frustrated
Satisfied
Done
```

AI根据状态改变：

```text
内容深度
信息密度
交互复杂度
主动程度
体验长度
```

例如：

### Curious

可以：

> 深一点。

### Tired

应该：

> 简单一点。

### Frustrated

应该：

> 降低复杂度。

### Satisfied

应该：

> 允许结束。

这比“猜你喜欢”高级得多。

---

# 二十八、我们真正要做的不是用户画像

传统产品容易形成：

```text
用户 = 标签集合
```

我们的方向应该是：

```text
用户
 =
长期倾向
+
近期状态
+
当前意图
+
正在发生的事情
```

其中：

> **当前意图 > 近期状态 > 长期偏好**

这是非常重要的权重关系。

---

# 二十九、第一分钟的完整体验

现在把前面压缩成真实用户路径：

```text
00:00
打开

↓
“现在想要什么？”

00:05
“发现点东西”

↓
“好，我来找一个。”

00:08
出现一个有趣的问题

↓
用户开始看

00:20
产生第一个疑问

↓
用户问

AI回答

↓
用户产生第二个问题

00:45
AI发现可以互动

↓
“我们直接试一下。”

01:00
用户开始操作
```

**如果第一分钟能够自然发生这条链，我们的产品就开始成立。**

# 三十、但第一分钟不能让所有用户都走同一条路径

另一个重要原则：

> **人本不等于统一体验。**

例如：

### 用户 A

“我想学东西。”

→ 深度探索。

### 用户 B

“我好累。”

→ 轻体验。

### 用户 C

“我想做个东西。”

→ 直接创作。

### 用户 D

“我不知道。”

→ AI承担选择。

### 用户 E

“我只想问一个问题。”

→ 直接回答。

所以真正的入口应该是：

```text
用户状态
      ↓
意图
      ↓
最短满足路径
```

而不是：

```text
所有用户
      ↓
同一个产品流程
```

---

# 三十一、产品的反成瘾设计

这一部分我要单独写进产品原则，因为它会影响未来商业化。

我们不追求：

> **最大化用户停留。**

而追求：

> **最大化用户满意地完成自己的意图。**

因此：

### 用户完成目标

→ 可以结束。

### 用户疲劳

→ 降低刺激。

### 用户不感兴趣

→ 快速退出。

### 用户明确拒绝

→ 不追问。

### 用户想继续

→ 给更深体验。

这会导致一个结果：

> 有时候我们会主动让用户离开。

我认为这是正确的。

因为如果长期成立，用户回来不是因为：

> “它让我停不下来。”

而是因为：

> **“它真的对我有用。”**

---

# 三十二、我们真正需要建立的信任循环

```text
AI理解我
   ↓
我发现它没有乱猜
   ↓
我愿意告诉它更多
   ↓
它理解得更准确
   ↓
体验变好
   ↓
我愿意回来
   ↓
我拥有更多控制权
   ↓
信任增加
```

而不是：

```text
AI知道很多
↓
AI操控推荐
↓
用户被动消费
↓
时长增加
```

这两条路线，长期价值完全不同。

---

# 三十三、最终的产品哲学

所以我现在会把我们的产品重新定义得更准确一点：

> **它不是一个“给人东西”的产品。**
>
> **它是一个帮助人理解自己此刻想要什么，并以最低成本进入那个状态的产品。**

有时候那个状态是：

> 放松。

有时候是：

> 好奇。

有时候是：

> 理解。

有时候是：

> 创造。

有时候甚至是：

> **什么都不想做。**

而一个真正以人为本的产品，必须允许最后一种答案存在。

# 三十四、下一层：真正进入设计与工程规格

逐屏逻辑现在已经确定。

下一步不应该再继续泛泛讨论“产品应该是什么”。

应该把这 11 屏进一步拆成四层：

### Layer 1｜视觉原型

每一屏：

- 具体布局
- 元素尺寸层级
- 信息密度
- 动画
- 手势
- 空状态
- 加载状态
- 错误状态

### Layer 2｜交互原型

每一个按钮：

- 点击之后发生什么
- AI什么时候回应
- 页面什么时候变化
- 用户什么时候可以打断
- 返回之后保留什么

### Layer 3｜AI行为规范

每一步明确：

- System Prompt
- Context
- User State
- Intent
- Decision
- Response
- Memory
- Safety

### Layer 4｜工程规格

最终形成：

```text
Frontend
     ↓
Experience Runtime
     ↓
State Engine
     ↓
Intent Engine
     ↓
Experience Planner
     ↓
Generation / Search / Tool
     ↓
Memory
     ↓
Analytics
```

然后才能进入真正的 MVP 开发。

# 三十五、下一轮最重要的事情

我建议我们**不要一次把所有页面继续做得越来越复杂**。

先把最关键的一段做到极致：

> **Screen 01 → Screen 02 → Screen 03 → Screen 04 → Screen 05**

也就是：

# 用户打开产品后的前 60 秒。

因为这里决定了一个最根本的问题：

> **用户到底会不会感觉：“这个东西真的在为我，而不是让我来适应它。”**

如果这一点成立，后面的互动、创造、记忆才有意义。

如果这一点不成立，后面所有 AI 能力都只是功能堆砌。

所以接下来我们应该把这 **前 60 秒做成真正可交付给 UI/UX 和工程团队的高保真原型规格**：逐个组件、逐个状态、逐个文案、逐个 AI 决策点设计，并同时做一次“反人性审查”，把所有可能让用户感到被推着走、被监视、被教育、被操控的地方逐一砍掉。
