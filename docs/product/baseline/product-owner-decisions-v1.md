## 1. 产品目标与不变原则

首个验证目标是证明：系统能围绕用户当前意图运行一个有限、可适应、可中断的体验，同时让用户可直接得到答案、纠正方向或停止。产品不是内容信息流或普通聊天壳。

继续冻结：当前明确意图优先；Runtime 是唯一状态写入者；State Machine 是唯一合法转换权威；LLM 只能提交提案；STOP 不可被后台生成覆盖；用户自主权、状态完整性与策略边界是 P0 硬门槛；测试全绿不等于产品通过。

## 4. 首体验与分阶段范围

### P3 首体验

冻结为探索型问题体验（Exploratory Question Experience），主目标为理解 / 探索。体验必须支持直接回答、解释原因、改变方向和停止，并留下状态与决策轨迹；不强迫继续，不以停留时长优化体验。

### P3-S1 运行时核心切片

纳入：Session、Intent、ExperienceState、State Machine、Semantic Action、Policy、LLM Gateway、Validator、Runtime、STOP、CHANGE、State Version、Events、Decision Trace、GS-01–GS-06。

WHAT_IF 已在 S1 允许动作中，因此必须实现规范所列基础 WHAT_IF → SIMULATE 并做契约验证；为保持最小切片，输出仅是当前运行提案，不建立完整多轮分支状态。若规范无法给出安全的单次模拟路径，则阻塞该动作，不得自行编造。

不纳入：完整 Creation、CREATE / MODIFY / SEARCH、完整 WHAT_IF 分支、跨会话持久 Memory、推荐系统、社交、信息流、完整创作 IDE、模板市场或多 Agent。

### 后续 P3-S2

候选范围：完整 WHAT_IF 分支、Correction、最小 Creation Branch，以及是否加入最小 Memory 的独立决议和验收。S2 不由本记录自动授权；须在 S1 证据复核后单独形成准入包。

## 5. Golden 与范围映射裁决

- S1 核心 Golden Suite 仍严格为原规范 GS-01–GS-06；不改名、不改预期结果。
- S1 基础 WHAT_IF 是已启用动作，必须有契约级正向、错误输入、事实/推断/假设区分和状态不越权测试；不冒充 GS-01–GS-06，也不让完整 P2 G03 提前 PASS。
- P2 G01–G08 是完整 P2 义务。G03 完整分支、G04 Creation、G07 Correction、G08 Memory Boundary 未在 S1 核心集通过，记为 NOT RUN / DEFERRED TO S2，直到对应行为真实实现并评测。
- 任何 P0 用户控制、状态写入、Policy / LLM 边界失败均直接阻断；不能由平均分抵消。

## 6. 发布指标

- 硬性验收：未授权状态写入、非法转换、陈旧结果覆盖、STOP / CHANGE 被忽略、Memory 覆盖当前意图均零容忍；适用 Golden 与契约测试必须全部通过。
- 统计指标：首体验匹配、意图完成、纠错恢复及延迟先作为观察指标；不在无真实用户基线时编造阈值。
- 面向公开发布的统计 Gate 必须预先定义人群、观察窗口、分子/分母、数据源、阈值和批准人；缺少批准时不得公开发布，但不阻止仅限内部的 S1 构建与受控验证。
- Session Time、Message Count、Voluntary Return、Continuation、Creation Start、Deepening 均不是 S1 硬门槛；禁止为提高停留或继续率削弱退出权。

### 动作优先级同层细化

C3 §4 将 WHY、WHAT_IF 等动作列为同一优先级层；S1 §12 的 WHY > WHAT_IF 只用于同层候选冲突时确定解释顺序，不表示 WHY 获得更高授权或 Policy 权限。若输入同时含 STOP、CHANGE_DIRECTION 等更高优先级动作，仍按 C3 / State Machine 原规则处理。该细化不改变启用动作集合；未覆盖的歧义输入不得由 LLM 自行选定。

## 8. 工程栈与 AI 编码治理

- 采用 ADR-0001：TypeScript + Next.js App Router 模块化单体，Node.js 24 LTS；用具备受控生命周期的 Node.js 服务 / 容器，不以静态导出或短时无状态函数承载可取消生成。
- 本决策不选择数据库、云厂商、身份系统、模型供应商、视觉稿或公开发布环境。
- Runtime 是唯一写入者；持久化版本比较须用原子条件保证，不能依赖进程内锁。
- LLM 返回仅为 Proposal；必须经 Validator、Policy 和 State Machine 后才交 Runtime。
- STOP / CHANGE 必须取消生成、使旧候选失效，并以状态版本拒绝迟到响应；关键决策可追踪。
- 每项编码任务必须引用已批准契约条款、输入输出、验收案例、禁止行为和回滚边界。修改契约 / Golden 期望须先经产品负责人版本化批准。
- 代码作者不得独立宣布 Gate PASS；复核人须与对应实现作者不同。G5 前指定独立评测负责人。
