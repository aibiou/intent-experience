## 3. S1 子集与完整义务

- S1 仅执行由获批映射明确纳入的核心子集；每个纳入案例必须有正向、负向及适用的边界/异常证据。
- P2 G01–G08 保留为完整验收义务。未纳入 S1 的案例标为 `NOT RUN / DEFERRED`，同时写明后续切片与责任人；它们不视为通过。
- 任何映射不得仅凭编号或名称相似推定等价。范围裁决见 PODR-001；CC01 / CC02 各类案例的逐项静态一致性仍待非作者和评测负责人复核。
- C4 独立权威未成立、SRC-23 迁移处置未由 AI 架构负责人确认时，G1/A1 不通过，不能进入编码前授权。

## 4. 通过语义

- **编码前准入通过**只意味着“允许按获批范围实现”，不意味着运行时正确、P2 CLOSED 或 P3 产品验收通过。
- **编码后动态证据通过**必须来自指定代码、契约、Prompt、Model、Policy、Schema 与评测语料版本的真实执行。
- 任一 P0 失败直接阻断；平均分、其他案例通过或测试全绿均不能抵消。
- 只有全部适用 Gate 有可追溯证据并完成正式签署，才可按获批治理文件更新关闭状态。

## 5. 批准与版本控制

权威 E8 登记与准入授权仍需完成以下证据动作：

1. 按本已采纳修订更新 E8 / P2 Exit Gate 的权威索引，记录替代关系、生效版本、决策人和日期；
3. 确认 P2 Closure、P3 Entry、P3-S1 Exit 之间的状态转换及签署人；
4. 将 Gate 证据路径和独立评测安排写入 E5；
5. 更新 `decision-register.md` 与 `readiness-record.md`。
