# 个人体验引擎 UI/UX 规范 v1

**状态：** 当前实现方向
**适用范围：** 首页、种子入口、体验对话、续作输入、模型服务配置
**产品原则：** 人决定方向，AI 降低成本。

这份规范记录当前代码采用的交互与视觉方向，帮助后续页面保持一致。它不改变产品状态机、生成策略、媒体流程或数据契约；需要改变这些行为时，应单独评估。

## 1. 体验目标

界面帮助用户以较低心理成本开始探索，并始终让用户决定方向、节奏和结束时机。

- 直接输入是首页的首要入口；状态选项是轻量替代路径。
- 入口文案帮助用户决定“从哪里开始”，不替用户预设兴趣或目标。
- 体验进行中优先呈现当前内容与可继续的动作；系统状态清楚、克制。
- 用户主动结束时自然收束，不追加推荐、排行榜或强制反馈。
- 模型和接口细节默认收起，只在用户进入开发者视图后展示。

## 2. 页面目标与层级

### 首页

**用户目标：** 用一句话开始，或选一个符合当前状态的入口；之后可回到最近探索或查看作品。

**层级：** 自由表达 → 四种状态入口 → 最近探索与作品。记忆和配置为安静的次级入口。

**交互：** 输入提交后直接开始；状态卡仅说明方向，不制造步骤感；“随便看看”保持可选且不打断输入。

### 种子入口

**用户目标：** 判断一个主题是否值得进入，并选择轻量切入角度。

**层级：** 类别提示 → 主题问题 → 可选上下文 → 入口角度 → 开始探索 / 换一个 → 自由输入。

**交互：** 任一入口角度都开始同一体验流程；“开始探索”使用种子默认角度；换一个只替换主题，不产生额外确认步骤。

### 体验对话

**用户目标：** 阅读当前回应、选择下一步或自由追问，并能随时停止。

**层级：** 当前主题与阶段 → 对话和作品 → 快捷回应 → 输入框。

**交互：** 快捷动作始终是用户可理解的普通表达；内容生成中输入行为保持现有规则；停止和完成作为正常结束路径呈现。高成本或耗时的媒体生成在提交前说明影响并允许用户确认。

### 续作输入

**用户目标：** 基于已完成作品表达下一次修改。

**层级：** 返回 → 原作品主题 → 续作说明 → 单一输入。

**交互：** 输入就是新一轮续作要求；不引入新的配置步骤或推荐。

### 模型服务配置

**用户目标：** 了解哪些能力可用，并在需要时管理服务。

**层级：** 页面名称与返回 → 当前能力摘要 → 开发者视图 → 按模态分组的服务 → 添加服务。

**交互：** 普通视图显示面向用户的连接状态；开发者视图才显示模型名与接口等细节。测试、刷新、设默认、删除等动作沿用明确的逐项操作和反馈。

## 3. 视觉语言

### 色彩

沿用浅纸色与深石墨色，以琥珀色标记行动、焦点和探索感。色彩应承担状态含义，不作为装饰堆叠。

| 用途 | 当前值 / 类别 | 使用方式 |
|---|---|---|
| 页面底色 | `#f7f6f1`、`#f3f1ea` | 首页、体验、配置页面的柔和底色 |
| 表面 | `white` / 半透明白 | 输入、卡片、摘要；与底色保持细微区分 |
| 主文字 | Tailwind `stone-900` | 标题和主要操作 |
| 次文字 | Tailwind `stone-500` | 说明、上下文、次级信息 |
| 弱文字 | Tailwind `stone-400` | 时间、提示、元信息；避免承载关键说明 |
| 品牌强调 | Tailwind `amber-700` / `amber-800` | 重点动作、选中/默认状态、键盘焦点 |
| 成功 / 错误 | `emerald` / `red` | 连接、失败等明确状态，并配合文字说明 |

保留低对比装饰背景；正文、按钮标签、状态说明必须有足够对比。不要只用颜色表达成功、失败、选中或禁用。

### 字体与排版

- 正文沿用 Geist sans；展示标题使用 Georgia 与系统中文宋体回退，限于首页主标题、主题问题和续作主题。
- 页面标题与正文明确区分；时间、轮次和模型名作为辅助信息，不抢主内容。
- 标题使用自然短句，说明写清动作结果；避免产品内部术语出现在普通用户路径中。

### 形状、留白与标记

- 卡片通常使用 `rounded-2xl`；输入框在宽屏呈胶囊形，在窄屏可使用更稳定的圆角矩形。
- 描边轻、阴影少；通过留白、字号和对齐建立层级，避免每块内容都套一张卡片。
- 轨道图与小型轨道标记代表“当下可选择的方向”，只在首页作识别元素，不重复用于功能无关的页面。

## 4. 组件与反馈约定

- **主要动作：** 每个区域最多一个明显主动作；使用具体动词，例如“开始探索”“发送”“回到首页”。
- **状态入口：** 图标、标题和一句解释组合成一个可点击区域；整张卡片可点击，焦点环清晰。
- **输入：** 提示语示例化而非命令化；保留可见焦点状态、字数约束及禁用反馈。
- **卡片：** 默认态安静；悬停只轻微提亮/上移；窄屏触控状态不依赖 hover。
- **加载：** 使用与最终内容形状接近的 skeleton；异步操作显示正在进行，不制造虚假完成状态。
- **空态：** 说明当前没有什么，并给出紧邻的下一步；避免空白区域或无目的的插画。
- **失败：** 说明发生了什么以及可执行的补救动作；保留用户已输入内容，除非现有流程另有明确约定。
- **耗时操作：** 提前说明等待时间或可能影响；等待中持续显示状态，完成后更新到结果。

## 5. 动态与无障碍

- 动画只用于页面切换、内容出现和轻微交互反馈；不循环闪烁或抢焦点。
- 尊重 `prefers-reduced-motion`：关闭非必要位移和持续动画，保留状态可辨识性。
- 保持语义标题顺序、原生按钮/链接行为、输入可访问名称和可见键盘焦点。
- 装饰图形使用 `aria-hidden`；状态与错误文字不只依赖图标或颜色传达。
- 点击目标保持足够尺寸，窄屏布局不横向溢出；键盘用户可以依序到达所有操作。
- 媒体内容提供正确的替代文本或原生播放控件；自动播放默认关闭。

## 6. 响应式原则

- **窄屏：** 单列优先；输入和主动作保持易触达；不让纯装饰压缩正文。轨道装饰可以隐藏。
- **中屏：** 状态入口切为双列；对话宽度维持可读行长。
- **宽屏：** 首页采用“文字与输入 + 轨道图”的并列布局，状态入口可四列；作品和最近探索并排展示。
- 配置卡片根据可用宽度增加列数；控件和说明在空间不足时换行，不截断关键状态。

## 7. 实现约定

- 以 `src/app/globals.css` 中的 `home-*`、`experience-shell`、`config-shell` 样式及 Tailwind utility 为当前实现来源。
- 新页面先复用现有颜色、输入、按钮、卡片和焦点样式；确实需要新视觉元素时，再新增有明确语义的局部类。
- 共用 CSS 只用于跨页面 token 或重复模式；页面专属造型留在组件局部样式，避免全局选择器影响其他路由。
- UI 改动应保持现有用户流程与行为契约；若更改可用动作、生成确认或数据展示规则，需同时更新对应产品说明。
