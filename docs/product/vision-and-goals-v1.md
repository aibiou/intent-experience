## 一、产品愿景

**个人体验引擎：让每个人都能从好奇走到创造。**

用户提出一个问题，引擎陪伴他走完一整段体验：

```text
好奇 → 理解 → 尝试 → 发现 → 创造 → 修改 → 完成
```

AI 不是更快的内容机器，而是体验的陪伴者：

- **不替用户思考**——先激发好奇，再给解释；解释之后给模拟，模拟之后给创造
- **不假装**——没接入的能力如实说没接入，不编造产物
- **不越权**——大模型只产出文本，状态写入由引擎唯一完成（GS-06）

体验的产物（图像 / 语音 / 视频）不是附属功能，而是「理解之后自然地把它变成自己的东西」的必经之路。

## 三、目标

### 近期（G1：媒体闭环）

1. **视频模态稳定产出**——上游容量恢复后 e2e 验证「生成一段视频」全流程（产物可播放、可在作品墙呈现）
2. **作品墙（Works Wall）**——历史媒体产物按会话归档、可回看（数据已在 data/media/ 落盘，缺呈现层）
3. **配置可发现性**——设置页展示每个模态当前默认提供方，未配置模态给出明确指引

### 中期（G2：体验纵深）

4. **记忆跨会话**——用户偏好与历史在会话间延续（记忆持久化已完成，缺语义回忆）
5. **创作闭环**——对已生成产物「再修改」（参考图生图、语音重合成），而非每次从零开始
6. **多提供方容灾**——同模态备选提供方故障时自动切换（解析链已支持显式指定，缺自动故障转移）

### 远期（G3：体验编排）

7. **多模态体验编排**——一次好奇驱动「讲解 + 配图 + 朗读」的组合体验
8. **体验模板化**——把验证过的体验路径沉淀为可复用种子（catalog 已有 18 条体验种子）

## 四、架构原则（不变式）

1. **引擎与提供方解耦**——主应用经本机模型网关（127.0.0.1:3031）调用一切模型；提供方可换，引擎不动
2. **密钥不出本机**——提供方配置（providers.json）入库共享、人人同一份；密钥只存本地（secrets.json，gitignored）
3. **LLM 不写状态**——大模型输出经策略映射为语义动作，状态迁移由状态机唯一执行
4. **诚实边界**——未接入 / 未配置 / 上游失败时给用户真实原因，不伪装成功
5. **无验证不宣称**——每个能力以可复跑的 e2e 证据为准（退出码 0 ≠ 产品正确）

## 五、非目标（现阶段不做）

- 不做多用户账号体系（单机个人引擎）
- 不做提供方密钥托管上云
- 不做开放式内容平台（作品默认本地保存，分享是显式动作）
