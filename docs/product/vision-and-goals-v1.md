## 一、产品愿景

**个人体验引擎：让每个人都能从好奇走到创造。**

用户提出一个问题，引擎陪伴他走完一整段体验：

```text
好奇 → 理解 → 尝试 → 发现 → 创造 → 修改 → 完成
```

AI 不是更快的内容机器，而是体验的陪伴者：

- **不替用户思考**——先激发好奇，再给解释；解释之后给模拟，模拟之后给创造
- **不假装**——没接入的能力如实说没接入，不编造产物
- **不越权**——大模型只产出文本，状态写入由引擎唯一完成（GS-06）

体验的产物（图像 / 语音 / 视频）不是附属功能，而是「理解之后自然地把它变成自己的东西」的必经之路。

## 三、目标与阶段

### 当前阶段（G1.1：可靠连续体验闭环，2026-10-17 起）

当前阶段不再以“接入更多模型”为目标，而是让已接入能力在真实使用中连续、可信、可恢复。判断标准不是单次请求成功，而是用户离开、返回、重试、继续创作时，体验不丢失、不重复扣费、不误导。

1. **长耗时媒体任务后台化**
   - 任务在发起时持久化；状态、进度、失败原因、产物可查询。
   - 用户刷新页面、切换会话或关闭标签后，运行中的任务继续推进；回到产品能恢复计时和结果。
   - 同一意图短时间不重复创建付费任务；失败可显式重试。
   - 验收：真实视频任务发起后刷新/切换会话，返回时能看到“运行中/已完成/失败”之一，且不产生重复生成。

2. **图像到视频的上下文接续**
   - 用户已有图像后说“把它做成视频”，系统应显式携带或明确引用该图像；不能悄悄退化为全新文生视频。
   - 若当前视频提供方不支持图生视频，必须如实说明能力和降级方式。
   - 验收：图像→视频链路保留主体与画面意图；用户能在结果说明中看到它基于哪张图。

3. **提供方与默认策略稳定**
   - 图像默认保持元宝本机桥；视频默认只在用户明确确认后指向会消耗额度的通道。
   - 本机桥有健康状态、队列锁和清晰错误；自动化不得抢占用户前台焦点。
   - 同模态备选只在契约与成本边界明确后参与故障转移。
   - 验收：默认项展示、健康探测、失败原因和重试路径一致，不把“未配置”伪装成“生成中”。

4. **候选结果成为创作素材**
   - 多候选图可在画廊中比较、选择；选择结果持久化为会话上下文。
   - 后续“换一张”“以此续作”“做成视频”优先使用用户选择的那张，而不是隐式取最新图。
   - 验收：从 4 张候选中选择后继续修改或续作，产物说明和参考图证据指向所选图。

5. **成本与等待预期前置**
   - 付费、长耗时或可能进入队列的任务在发起前说明影响。
   - 运行中显示阶段、预计时长和可安全离开的提示；完成后自动回到会话或作品区。
   - 验收：用户在确认前能知道是否付费，发起后能离开并安全返回。

### 后续阶段（G2：创作纵深）

6. **记忆跨会话**——用户偏好与历史在会话间延续；语义回忆替代简单拼接。
7. **跨会话续作**——作品墙回看后可稳定携带所选产物进入新体验。
8. **图像编辑与迭代**——局部修改、风格迁移、多轮版本树可追溯。
9. **多提供方容灾**——同模态备选提供方在明确成本和契约边界内自动切换。

### 远期（G3：体验编排）

10. **多模态体验编排**——一次好奇驱动“讲解 + 配图 + 朗读 + 视频”的组合体验。
11. **体验模板化**——把验证过的体验路径沉淀为可复用种子。
12. **真实用户反馈闭环**——用非产品负责人的真实使用结果决定后续优先级。

## 四、架构原则（不变式）

1. **引擎与提供方解耦**——主应用经本机模型网关（127.0.0.1:3031）调用一切模型；提供方可换，引擎不动
2. **密钥不出本机**——提供方配置结构可共享；API Key 只以 AES-256-GCM 密文存于本机，加密密钥经本地环境注入
3. **LLM 不写状态**——大模型输出经策略映射为语义动作，状态迁移由状态机唯一执行
4. **诚实边界**——未接入 / 未配置 / 上游失败时给用户真实原因，不伪装成功；元宝本机桥只声明图像能力，不冒充视频提供方
5. **无验证不宣称**——每个能力以可复跑的 e2e 证据为准（退出码 0 ≠ 产品正确）
6. **本机控制不越界**——元宝 / 豆包本机桥只做后台适配与结果回收，不得抢占用户焦点、覆盖用户窗口或干扰手动使用

## 五、非目标（现阶段不做）

- 不做多用户账号体系（单机个人引擎）
- 不做提供方密钥托管上云
- 不做开放式内容平台（作品默认本地保存，分享是显式动作）
- 不在用户未明确确认的情况下自动触发付费或长耗时视频生成
- 不为了让接入数量更好看而添加没有真实产品链路验证的提供方
