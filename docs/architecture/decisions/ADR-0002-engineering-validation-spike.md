# ADR-0002：受限工程验证 Spike（STOP/CHANGE 取消与 stale 拒绝原型）

**状态：** EFFECTIVE（2026-10-08：产品负责人批准 + 架构 / 工程负责人会签齐备；仅授权 §2 三项验证）
**日期：** 2026-10-08
**决策范围：** 一次性、非产品化的技术可行性验证；**不授权任何产品运行时代码**
**关联：** ADR-0001（取消条款与其"原型不过则撤销推荐"出口）、P3-S1-REVIEW-003 §6（启动死锁）、independent-review-package.md v1.2.0 R4-5、P2-EVIDENCE-8.1 A6
**已以 PD-14 记录（PODR-001 v1.0.3）：** 批准范围极窄、非产品化的工程验证 Spike，用于在 P3-S1 实施授权前验证目标平台的取消与 stale 拒绝可行性；Spike 不实现产品契约、不产生 Gate/Golden/动态证据、不计入 S1 进度，其代码一次性且不并入产品代码库。

## 1. 背景与问题

现行门禁存在启动死锁：

```text
A6 签署前置：STOP/CHANGE 端到端取消 + stale 拒绝原型完成
        ↓
A6 是实施授权（A1–A6）的前置
        ↓
唯一的代码许可是 P3-S1 Runtime Implementation = NOT AUTHORIZED
        ↓
原型的合法许可不存在
```

本 ADR 的目的就是给这个原型一个独立的、范围极窄的许可证，**而不是放宽 A6 或 R4-5**。

## 2. 验证目标（仅此三项）

| # | 验证项 | 通过标准（可复现演示 + 记录） |
|---|---|---|
| S-1 | 客户端中止传播：用户侧断开/Abort 后，服务端生成任务（含 streaming 响应）可被确定性地取消，无静默续行 | 取消信号端到端可达；取消后无新 chunk 写出；任务终止有日志与时间戳证据 |
| S-2 | stale 响应拒绝：携带旧 `expected_state_version` 的迟到响应被原子条件写拒绝（`STATE_VERSION_CONFLICT` 语义），不覆盖新状态 | 并发时序下旧版本写入 100% 拒绝；拒绝路径有可审计记录；无 overwrite/auto-merge/silent-discard |
| S-3 | 持久层条件写能力：候选存储（见 §4）支持版本条件原子更新，不依赖进程内锁 | 同一版本并发竞争恰有一个成功；失败方读到最新版本 |

三项均须在**目标部署形态**（常驻 Node.js 服务/容器，非静态导出、非短超时 serverless）下验证。

## 3. 范围与禁止项（硬边界）

**允许：** 沙箱目录（建议 `spike/cancellation/`）内的一次性验证代码；最小路由/任务/存储桩；技术验证报告。

**禁止（全部为硬边界，违者即越权实现）：**

1. 不实现任何产品契约对象：Session、Intent、ExperienceState、Semantic Action、Policy、LLM Gateway、Validator、Runtime 一概不建；
2. 不接入、不复制、不"简化版实现"C01–C09、GS-01–GS-06、CC02 案例体系；
3. 不调用真实 LLM Provider（用固定延迟/可中止的桩即可，验证的是取消与并发语义，不是模型行为）；
4. 不收集任何真实用户数据；不引入产品 schema、产品 API 契约；
5. 不产生任何 Gate、Golden、G2–G5、A 条件的证据——Spike 报告**只能**作为 ADR-0001 技术可行性复核的输入；
6. 不计入 S1 进度、不作为实施授权的"部分完成"；
7. Spike 代码一次性：验证结束后归档或删除，**永不并入**产品代码库；若后续实现需要类似代码，须在获准的实施范围内重写并走正常契约/测试流程。

## 4. 技术基线

- 运行时与框架：与 ADR-0001 一致（Next.js App Router + TypeScript，常驻 Node.js 服务/容器）；Node.js 具体版本按 ADR-0001 生命周期规则在启动时锁定补丁并记录。
- 存储候选：允许在 PostgreSQL / SQLite（含事务）/ 等具备原子条件写能力的候选中选一种做 S-2/S-3 验证；**本 ADR 不决定产品数据库选型**，选型仍属未决项。

## 5. 结果处置

- **全部通过：** 报告附入 ADR-0001 复核材料，作为架构/工程负责人签署 A6 技术可行性部分的输入之一（A6 其余前置不变）。
- **任一失败：** 触发 ADR-0001 重议（含改评估方案 B），按 ADR-0001 原文"不得降低验收标准"执行；失败结果必须如实登记，不得重跑至通过为止而不留失败记录。
- 报告版本化存放于本 ADR 同目录（`ADR-0002-spike-report.md`），含环境、版本锁定、原始记录路径与 SHA-256。
